# СВОЗ · цифровой деканат

**СВОЗ** — цифровой деканат вымышленного учебного заведения. Это конкурсный прототип с синтетическими данными. Для проверки используйте демоаккаунты, реальные документы и персональные данные вводить не нужно.

**[Открыть публичный стенд](https://svoz.evgfactory.ru/)**

- **Студент** видит расписание на день и неделю, переносы, успеваемость, заметки, задачи и уведомления. Может запросить справку и переписываться с деканатом.
- **Сотрудник** обрабатывает назначенные обращения, отвечает студентам и обновляет статусы.
- **Кампус** объединяет афишу, клубы и личные планы. Студенты записываются и предлагают события, деканат рассматривает предложения и публикует официальные мероприятия.
- **Помощник** подключается по согласию. Он отвечает по разрешённым данным, предлагает заметки и дела, помогает студенту и сотруднику составить черновики.

## Стек и архитектура

Python 3.12 и стандартная библиотека обслуживают JSON API и статический интерфейс на HTML, CSS и JavaScript. SQLite хранит профили, расписание, задачи, обращения и сессии. Сервер проверяет роль и доступ к каждой записи. На публичном стенде каждому профилю браузера выделяется отдельная база. Подробнее в [документации по архитектуре](contest/architecture.md).

## Локальный запуск

Установите Python 3.12 или новее. Из папки проекта запустите:

```powershell
python server.py
```

Откройте [СВОЗ на этом компьютере](http://127.0.0.1:8000). При первом запуске сервер создаст SQLite и добавит вымышленные данные, привязанные к дате создания базы. Зависимости приложения входят в Python.

| Логин | Демонстрационная роль |
| --- | --- |
| `student1` | Студент с переносом занятия и ближайшими сроками |
| `student2` | Студент с другим профилем и учебными данными |
| `dean` | Сотрудник деканата |

Общий пароль трёх демонстрационных аккаунтов — `SvozDemo2026!`. В публичной конфигурации каждый профиль браузера получает отдельный стенд с этими логинами. Локальный запуск по умолчанию использует одну общую демонстрационную базу.

## Что посмотреть

1. Войдите под `student1`. Откройте перенос занятия и сравните время и аудиторию. Перейдите к расписанию на неделю.
2. В «Учёбе» найдите ближайший срок. Создайте личную задачу или добавьте заметку к занятию.
3. Оформите справку. Выйдите и в том же профиле браузера войдите под `dean`. Откройте заявку, смените статус и ответьте. Снова войдите под `student1` и проверьте переписку и уведомления.
4. Войдите под `student2` и сравните учебные данные. Попробуйте светлую и тёмную темы.

## Помощник

По умолчанию выключен. Для подключения задайте переменную `POLZA_API_KEY` в окружении процесса или сохраните её в локальном файле `.env` рядом с `server.py`. Можно скопировать `.env.example` и заполнить пустое значение. Приложение использует `https://polza.ai/api/v1/chat/completions` и модель `deepseek/deepseek-v4.1-flash`. Перезапустите сервер после настройки. Файл `.env` исключён из Git, образа и архива.

Студент и сотрудник отдельно соглашаются на передачу ограниченного контекста в Polza AI в текущей сессии. Студент подтверждает заметки, задачи и сообщения в существующей заявке. Черновик новой заявки открывается в обычной форме. Сотрудник получает черновик ответа, выжимку, список уточнений и справку по вымышленным правилам. Статусы и отправка от лица сотрудника остаются ручными.

ИИ использует нативный вызов функции для структурированного ответа. При явном отклонении параметров функции сервер один раз повторяет запрос с форматом JSON. Лимиты: 20 обращений на сессию, 40 на аккаунт и 80 на экземпляр в час. История диалога видна до перезагрузки, выхода или выключения ИИ. Информация о токенах и расходе поступает вместе с ответом, если её предоставил провайдер.

Команда `python tests/live_polza.py` запускает платную проверку на отдельной демонстрационной базе и показывает учёт токенов и рублей. Запускайте её только при осознанной проверке провайдера. Обычные автоматические тесты используют подменённые ответы.

## Проверки

Используйте отдельную пустую базу для автоматических сценариев. API-тесты создают тестовые записи.

```powershell
$env:SVOZ_DB = Join-Path $PWD 'test-results/api.sqlite3'
python server.py --port 8001
```

В другом терминале:

```powershell
python tests/test_api.py
python tests/test_assistant.py
python tests/test_polza.py
```

Для браузерного сценария используется Node.js и Playwright. Установите Playwright локально командой `npm install --no-save playwright` и Chromium командой `npx playwright install chromium`. Запустите `node tests/browser.cjs` с работающим сервером на порту 8001. Можно задать `SVOZ_TEST_URL`, `PLAYWRIGHT_MODULE` и `CHROMIUM_PATH`. Для воспроизводимости запускайте проверки на свежей демонстрационной базе.

## Развёртывание

Конкурсный стенд — [svoz.evgfactory.ru](https://svoz.evgfactory.ru/). На VPS приложение работает в отдельном сервисе `systemd`; Caddy принимает HTTPS и передаёт запросы на localhost. Снимки и результаты внешней проверки приведены в конкурсных материалах.

Подробные шаги для REG.RU и Caddy — в [инструкции публикации](deploy/runbook.md). Готовый Compose включает отдельный том SQLite, политику перезапуска, лимиты ресурсов и вход через `127.0.0.1:18080`. Сервисный ZIP предназначен для VPS, архив исходников — для жюри.

В публичной конфигурации переключайтесь между ролями через выход и вход **в том же профиле браузера**. Чтобы начать с исходных данных, используйте новый приватный профиль или очистите данные сайта. У другого профиля браузера будут независимые записи даже при тех же конкурсных логинах.
