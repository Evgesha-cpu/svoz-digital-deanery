# Как ставили задачи ИИ

**Приложение к конкурсному отчёту · первая сборка**

В исходном промпте владелец попросил создать «полноценный работающий конкурсный прототип СВОЗ» и отдельно указал: «Не придумывай промпты, диалоги, результаты тестирования и другие доказательства, которых не было». Исследование и решения v2 определили три сценария. Студент узнаёт о переносе, находит ближайшее учебное дело и получает ответ деканата внутри заявки.

**Сервер и интерфейс.** Codex поручил серверному агенту: «Implement Python stdlib SQLite backend, seed/auth/all operations and provider integration». Агент сообщил: «Staff ownership via explicit assigned_to per request». Это решение связало обработку обращения с назначенным сотрудником. Агент интерфейса получил задание «Implement student and staff UI, own web/ directory» и согласовал с серверным агентом общий контракт API.

**Независимая проверка.** Агент ревью получил задачу «Focus on actionable security and product bugs, communicate promptly, no edits». Он обнаружил, что ссылка «К содержанию» меняла фрагмент адреса и возвращала пользователя на главную. Исправление проверили клавиатурой в Chromium. Ревью также подтвердило привязку согласия на ИИ к сессии и проверку доступности записей, на которые ссылается модель.

**Обратная связь с браузерного теста.** Главный агент передал разработчику интерфейса: «Student hash navigation to notifications uses stale dashboard». После исправления агент ответил: «Request/notifications navigation now refreshes dashboard». Повторный прогон подтвердил переход от ответа деканата к уведомлению студента. Отдельно исправили перерисовку формы сотрудника, которая могла стереть уже набранный ответ при смене статуса.

**Инструменты и сервисы.** Codex Desktop и его субагенты готовили код, дизайн, тесты и тексты. Два визуальных референса предоставил владелец. Для интерфейса использованы HTML/CSS/JavaScript и встроенные SVG. Playwright и Chromium проверяли сценарии и снимали экраны, Python и unittest проверяли API, SQLite хранила данные. ReportLab, Pillow, pypdf и Poppler использованы для подготовки и проверки отчёта. Git, GitHub CLI и GitHub использованы для публикации исходников, REG.RU, SSH, systemd и Caddy — для работы стенда. Polza AI и DeepSeek обслуживают функции помощника в приложении. Docker Compose подготовлен как альтернативный путь установки.

Снимок первого рабочего прогона сохранён рядом с финальными. Раннее визуальное исследование описано в исходных материалах. Отдельный снимок макета в доступной истории не зафиксирован.

# Как проверяли помощника и публикацию

**Приложение к конкурсному отчёту · проверенные изменения**

**Постановка интеграции.** Из промпта владельца: «ИИ предлагает действие, интерфейс показывает его параметры, студент подтверждает, сервер выполняет и возвращает результат». Серверная инструкция начинается с «Отвечай по-русски и опирайся только на разрешённый контекст». Модель возвращает предложение. Право на запись и факт отдельного подтверждения проверяет сервер.

**Ошибка в предложении сообщения.** Первый реальный вызов не вернул подходящее действие. Для открытой заявки в инструкцию добавили тип message и числовой идентификатор этой заявки. При повторной проверке сообщение появилось в переписке после подтверждения. Второе подтверждение того же предложения вернуло отказ. Это проверялось запросом к реальному API.

**Проблема после согласия сотрудника.** В браузере панель помощника сворачивалась при обновлении после согласия. Исправление сохранило её раскрытой. В финальном проходе реальный черновик ответа вставился в редактируемое поле. Саму отправку контролирует сотрудник.

**Проверки по уровням.** Локальные тесты с подменой ответа покрыли правила доступа, отмену, подтверждение, лимиты и отказ провайдера. Реальные запросы Polza подтвердили нативный вызов функции, ответы по расписанию и оценкам, сохранение предложенных дел и режимы сотрудника. На VPS отдельно проверены HTTPS, три роли, изоляция посетителей, обработка заявки, подтверждение заметки и сохранение сессии и данных после перезапуска. Доступность из РФ без VPN отдельно не проверялась.

**Ручные действия.** Владелец выбрал продуктовую концепцию и визуальное направление, предоставил требования и референсы, настроил DNS, восстановил доступ по SSH и выполнил административную установку и перезапуск. Он также исправил формулировку о географии проверки в PDF. Исправленные страницы сохранены в начале этого документа.

Полные материалы находятся в публичном репозитории Evgesha-cpu/svoz-digital-deanery, в каталоге contest: prompt-owner.md, prompt-polza.md, process.md, verification.md и screenshots/.
