# СВОЗ — полноценная интеграция ИИ через Polza AI

Продолжай разработку существующего проекта СВОЗ («Современное Вайбоградское Обучающее Заведение»).

Основное приложение уже разработано и прошло первоначальные тесты. Сейчас необходимо подключить настоящий ИИ через Polza AI, реализовать и проверить интеллектуальные функции студента и сотрудника деканата.

**Не переписывай готовое приложение.** Изучи существующую архитектуру и максимально используй то, что уже реализовано.

## 1. Подключение API

Провайдер: Polza AI.

Настройки:
- Base URL: `https://polza.ai/api/v1`
- Модель: `deepseek/deepseek-v4.1-flash`
- API-ключ: переменная окружения `POLZA_API_KEY`

API-ключ уже создан.

Сначала проверь, имеется ли ключ в локальном окружении проекта. Если его нет, подготовь `.env` и `.env.example` и сообщи мне, куда именно добавить ключ. Не требуй отправлять секрет в чат.

Никогда не выводи ключ в логи, тесты, документацию или пользовательский интерфейс. Убедись, что `.env` исключён из Git и архивов исходного кода.

Используй OpenAI-совместимый API Polza AI. Не добавляй тяжёлые библиотеки и агентские фреймворки без необходимости.

## 2. Возможности ИИ для студента

ИИ должен быть полноценным помощником внутри СВОЗ, а не просто отдельным чат-ботом.

Реализуй:

**Вопросы о студенте**
- Какое у меня завтра расписание?
- Какие задания скоро сдавать?
- Что осталось закрыть по математике?
- Когда ближайший экзамен?
- Какой статус моей заявки?
- Какие изменения произошли в расписании?

Помощник должен использовать реальные данные текущего тестового аккаунта из SQLite, а не придумывать информацию.

**Вопросы об университете**

Помощник отвечает на вопросы о вымышленном университете СВОЗ, правилах, документах и учебных процедурах.

Создай небольшую структурированную базу знаний, если существующей недостаточно. Отделяй установленные вымышленные правила университета от предположений модели.

**Работа с действиями**
- Создать заметку к конкретной дисциплине или занятию.
- Создать задачу или напоминание.
- Подготовить текст обращения в деканат.
- Создать черновик заявки.
- Отправить сообщение по существующей заявке после подтверждения.
- Помочь спланировать подготовку к экзаменам.

Примеры:
- «Напомни подготовиться к контрольной по физике».
- «Создай заметку, что на следующую пару нужно принести лабораторную».
- «Напиши деканату, что мне нужна справка об обучении».
- «Что мне нужно сделать до конца недели?»

Для действий используй function calling, если выбранная модель и API действительно его поддерживают.

Если function calling работает нестабильно, реализуй безопасный механизм структурированных предложений действий с серверной валидацией.

**Важно:** ИИ предлагает действие, интерфейс показывает его параметры, студент подтверждает, сервер выполняет и возвращает результат. Не выдавай предложение модели за уже выполненное действие.

## 3. ИИ для сотрудника деканата

Добавь только действительно полезные функции:

- Подготовка черновиков ответов на обращения студентов.
- Краткое содержание длинной переписки.
- Подсказка, какая информация требуется для обработки заявления.
- Поиск ответов в базе правил университета.

ИИ не должен самостоятельно отправлять сообщения, менять статусы заявок или принимать административные решения.

Сохрани текущий интерфейс сотрудника, добавляя функции органично и без перегрузки.

## 4. Интерфейс

Интегрируй помощника в существующую дизайн-систему СВОЗ.

Нужно:
- Удобный чат, доступный из основных разделов.
- Контекстные подсказки там, где они полезны.
- Быстрые действия и примеры запросов.
- Понятные карточки предлагаемых действий с подтверждением и отменой.
- История сообщений в пределах текущего аккаунта.
- Индикация генерации ответа, ошибок и успешных действий.
- Полноценная мобильная версия от 360 px.
- Поддержка светлой и тёмной тем.

Не создавай отдельный перегруженный интерфейс для ИИ. Он должен ощущаться естественной частью приложения.

## 5. Согласие и безопасность

Использование ИИ добровольное.

По умолчанию ИИ отключён. Перед использованием студенту нужно понятно объяснить, что необходимые данные будут передаваться стороннему API Polza AI, и получить явное согласие.

Обеспечь:
- Возможность отключить ИИ в настройках.
- Отсутствие обращений к модели без согласия.
- Передачу только минимально необходимых данных.
- Серверную проверку авторизации и прав на каждый запрос и действие.
- Невозможность получить данные другого студента.
- Защиту от prompt injection и попыток заставить модель обойти права.
- Серверную валидацию аргументов всех действий.
- Подтверждение пользователем любых изменений и отправки сообщений.
- Отсутствие API-ключа в браузере.

Сотрудник деканата также должен получать только разрешённые ему сведения.

Никаких настоящих персональных данных — только конкурсные демонстрационные.

## 6. Стоимость и надёжность

Проект конкурсный, поэтому важны низкие расходы и предсказуемость работы.

Реализуй:
- Разумные ограничения количества запросов на пользователя.
- Ограничение размеров контекста и ответов.
- Тайм-ауты и корректную обработку ошибок API.
- Контроль числа последовательных вызовов инструментов.
- Учёт расхода токенов, если он предоставляется API.
- Защиту от случайных циклов и чрезмерного расходования средств.

Не отправляй в каждом запросе всю базу данных. Подбирай необходимый контекст по вопросу студента.

Не ухудшай остальные функции приложения при недоступности ИИ.

## 7. Самостоятельное тестирование

После подключения выполни реальные запросы к Polza AI, используя действительный ключ.

Проверь:

1. Простой вопрос к модели.
2. Ответ на основе расписания студента.
3. Ответ на основе успеваемости.
4. Создание заметки после подтверждения.
5. Создание задачи после подтверждения.
6. Подготовку и отправку сообщения деканату.
7. Генерацию черновика ответа сотрудника.
8. Попытку получить чужие данные.
9. Попытку выполнить действие без подтверждения.
10. Поведение при отключённом ИИ.
11. Обработку ошибок API и превышения лимитов.
12. Мобильный интерфейс и обе темы.

Проверь фактическую поддержку function calling выбранной моделью.

Для значимых сценариев добавь автоматические тесты с подменённым API. Отдельно проведи несколько реальных интеграционных проверок.

Не подменяй реальные результаты тестовыми заглушками в итоговом отчёте.

Исправляй найденные ошибки и повторно проверяй.

Работай максимально автономно в рамках одного задания.

Самостоятельно изучай, реализуй, тестируй, исправляй и документируй.

Не останавливайся для промежуточного согласования решений, которые можно принять самостоятельно.

Не меняй существующий дизайн и основные функции без необходимости.

Не занимайся развёртыванием на публичном сервере — это будет отдельная задача.

**Если API-ключ доступен — сразу выполняй интеграцию и реальные проверки. Если ключ не обнаружен — подготовь всё, что возможно без него, и точно укажи, куда добавить ключ для завершения.**
