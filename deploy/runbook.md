# Публикация СВОЗ на REG.RU

Действующий адрес — https://svoz.evgfactory.ru/. На VPS выбран Python 3.12 и отдельный сервис `svoz.service`, потому что Caddy уже работал, а Docker был выключен. Установщик `deploy/install-systemd.sh` запускается администратором из закрытого каталога вместе с сервисным ZIP и отдельным файлом `polza.env`. Ключ переносится в `/etc/svoz/polza.env` с доступом только для root. Постоянное состояние находится в `StateDirectory=svoz`, прокси — в отдельном импорте Caddy. Текущие сайты и их настройки сохранены.

При обслуживании действующей установки используйте `systemctl restart svoz` и `curl -fsS http://127.0.0.1:18080/health`. Для приватной резервной копии остановите только `svoz`, скопируйте каталог состояния с сохранением прав и запустите сервис. Ниже приведён альтернативный порядок для хоста с Docker.

## До загрузки

1. Под уже авторизованным администратором проверьте `free -m`, `df -h /`, `uptime`, `systemctl status caddy docker` и `ss -ltn`. Определите фактический путь и импорты Caddy. Проверьте отсутствие уже существующего маршрута СВОЗ и свободный 127.0.0.1:18080. До включения сервиса оставьте запас выше лимита контейнера 192 MiB и место для образа и баз. При нехватке скорректируйте тариф или выберите отдельный VPS.
2. В зоне evgfactory.ru добавьте A-запись `svoz` со значением `194.226.122.99`, если это подтверждённый VPS. Проверьте ответы публичных DNS. AAAA добавляйте только при настроенном IPv6.

## Размещение

1. Распакуйте `svoz-deploy.zip` в отдельный каталог, например `/opt/svoz`. Установите права 0600 на локальный `.env` с `POLZA_API_KEY`. Не передавайте ключ параметром командной строки и не выводите развёрнутый Compose. Используйте `docker compose config --quiet`.
2. В каталоге СВОЗ выполните `docker compose up -d --build`. Убедитесь, что `curl -fsS http://127.0.0.1:18080/health` возвращает ok. Проверьте `docker compose ps`. Том `svoz_database` сохраняется при пересоздании контейнера. Docker должен стартовать вместе с системой.
3. Сделайте резервную копию действующей конфигурации Caddy. Добавьте отдельный блок из `deploy/Caddyfile` в существующую структуру импортов, сохраняя текущие сайты. Проверьте полный действующий конфиг через `caddy validate`, затем выполните штатный reload Caddy. При ошибке верните добавленный блок к предыдущему состоянию и повторно проверьте действующие сайты. Не перезапускайте чужие контейнеры.
4. Откройте HTTPS из внешней сети и проверьте сертификат и отсутствие доступа к `/.env`, файлам базы и служебному маршруту `/health`. Пройдите сценарии жюри и сравните результаты в двух независимых браузерах. Повторите чтение после перезапуска только `docker compose restart app`. Доступность из России без VPN отмечайте после такой проверки.

## База и восстановление

Публичный режим создаёт отдельную SQLite при первом входе в каждом профиле браузера. Выход сохраняет идентификатор стенда для смены роли. Чтобы начать с исходных данных, откройте новый приватный профиль или удалите данные сайта в браузере. Прежняя база при этом остаётся в серверном томе. На экземпляр настроен предел 120 стендов. При заполнении проверьте фактическую нагрузку и выделенный объём. Обслуживание тома планируйте отдельно.

Для резервной копии остановите только контейнер СВОЗ и снимите приватный архив его тома, затем сразу запустите его. Для отката к версии используйте предыдущий образ и сохранённый том. Для восстановления базы используйте отдельную копию тома и проверьте её перед переключением. Не удаляйте публичный том во время конкурса. База и архив резервной копии не должны лежать в веб-каталоге.
